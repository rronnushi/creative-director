# Find a direction

Understand the audience, purpose and constraints. Find the one idea that should organize the experience: what it makes easy, what it makes memorable and what it deliberately leaves out.

If the brief is open, offer a few meaningfully different approaches. Explain how each changes the composition, content and interaction—not just the font or colour. If the user has already chosen a direction, develop it instead of reopening the choice.

Recommend a direction and give a reason tied to the project. Turn descriptive words into decisions about type, colour roles, spacing, imagery, layout and motion. Include enough concrete detail for a builder to start, without pretending untested values are final.

For a photography archive, “contact sheet” could mean tightly aligned thumbnails, small captions and a viewer that returns to the same place. An editorial alternative could lead with one large image and a short story. The right choice depends on whether comparison or storytelling is the main task.

Use the taste reference as a starting point, not a style to impose. A quiet interface is not always better than an expressive one. Explain the tradeoff and a useful next step. Don't start coding when direction is all the user asked for.
