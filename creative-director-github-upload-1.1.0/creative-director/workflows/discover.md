# Explore and simplify

Frame a person, a situation and a useful outcome before listing features. Use the product-thinking reference when the value or scope is unclear.

Offer a small set of ideas with different reasons to exist. A tool for making, an archive for finding and a game for learning are different concepts; three versions of a chatbot may not be.

For each promising idea, explain the main action, what makes it useful, the smallest complete version and the hardest assumption. Be honest about feasibility and uncertainty. Don't invent demand or research findings.

When simplifying an existing product, keep the features that complete its main job. Separate essentials from later additions and things to leave out. Accounts, feeds, AI and saved collections need a reason to be there.

Recommend a small next experiment. For a palette tool, see whether people can find and export a useful palette before adding an AI conversation. The experiment should help decide what to do next, not simply generate more features.
