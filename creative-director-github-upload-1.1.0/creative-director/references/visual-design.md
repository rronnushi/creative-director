# Composition, type and colour

Use this when the page feels weak, inconsistent or hard to read.

Start with the order of attention. What should someone notice first, understand next and act on? Compare that with the rendered result. If every section has equal weight, adding decoration usually won't fix the hierarchy.

Look for shared alignment edges, a useful spacing rhythm and type roles that repeat. Fix relationships before adjusting every component individually. Whitespace should help the content; a professional table may need density while an artwork viewer needs room.

Choose type for its job: an expressive display face may suit a title, while controls and longer text need clarity at their real size. Check fallbacks, required languages, available weights and loading cost. Use relative sizing and test long headings and enlarged text.

Give colours roles—surface, text, accent, selected state and status—instead of inventing a new value for each component. OKLCH can help explore a palette, but pleasing colour relationships don't guarantee readable contrast. Light and dark themes need their own checks.

For WCAG AA, normal text generally needs 4.5:1 contrast and large text 3:1. Large text means at least 18pt, or 14pt bold. Check the actual foreground and background, including opacity and images. Controls and focus indicators have separate criteria; don't communicate status through colour alone.

A gallery might use one strong selection accent and quiet captions so the work leads. A festival site might use loud type and several saturated colours. Either can be coherent if the hierarchy and roles hold together.

Inspect the result with real content, small screens, long labels and relevant states. Keep a user's chosen personality rather than automatically replacing it with neutral styling.

For technical details, see the `typography`, `colour` and `wcag` entries in [sources](sources.json). The composition advice here is design judgment, not a measured user-study result.
