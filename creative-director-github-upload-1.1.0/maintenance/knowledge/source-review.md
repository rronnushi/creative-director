# Reviewing a source

Use primary documentation for technical claims. Record the document version or that it is living documentation, the review date, what was actually read and any unresolved gap in the installed source register.

Keep design preferences separate from claims backed by documentation. A reachable page does not prove accuracy, and a review date is not a promise that an API is unchanged.

Recheck version-sensitive guidance when it matters to a real implementation. Don't copy entire external manuals into the skill. See [the maintainer guide](../../docs/maintenance.md).
