# DISCOVER

Use product thinking and taste only where judgment is needed. Frame a concrete person, situation and unmet job before generating features.

Produce a small set of different value mechanisms, not reskins: an archive for discovery, an editor for making, and a game for learning can address the same topic differently. For each: main promise, smallest loop, distinctive constraint, evidence needed, technical uncertainty and what to omit. Compare desirability, feasibility and learning value; mark hypotheses rather than inventing market demand.

Recommend the cheapest experiment that could disprove the preferred idea. Example: test whether users can select a usable palette from 12 curated samples before building an AI palette chat system. The MVP must complete one valuable task; authentication, social feeds and recommendation engines are not default requirements. Deliver concepts and a testable shortlist, not code unless requested.
