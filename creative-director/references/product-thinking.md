# Product thinking

Load when the value, audience or feature scope is unclear.

## Principles

Define the job as person + situation + desired progress. A feature belongs in the MVP only if removing it breaks the central valuable loop or prevents learning a critical assumption.

## Decision framework

Map the journey from first input to useful outcome. Rank features by contribution to that outcome, confidence in need, implementation cost and ongoing burden. Separate evidence of demand from team enthusiasm. Prefer a reversible test for uncertain value.

## Implementation

Write a one-sentence promise and a must/next/omit list. Test the riskiest desirability assumption before optimizing delivery. Identify distribution, content ownership and maintenance responsibilities.

## Example and contextual exception

A palette archive can first let a visitor find, inspect and export a palette. Accounts and social ratings can wait. For a regulated collaborative workflow, identity and audit history may be essential to the first useful loop.

## Failure patterns

Counting features as value; inventing user research; mistaking novelty for demand; an MVP that cannot finish its main task.

## Validation

A new user can complete the central task with representative content. Every must-have traces to that task or a documented constraint. An experiment has an observable disconfirmation condition.

## Evidence boundary

The decision framework and examples are authored guidance, not findings from a user study. Technical source: **discovery** in [the source register](../knowledge/sources.json). See its version, review date, supported claims and freshness status. Recheck version-sensitive APIs against the installed package/browser before implementation.
