# Visual design

Load when composition, hierarchy, spacing or component coherence is at issue.

## Principles

Make the order of attention correspond to task importance. A grid is a relationship among content, not a demand for identical cards.

## Decision framework

Inspect at page, section and component scales. Count competing focal points; compare alignment edges and spacing roles. Change structure before adding shadows to separate indistinguishable content.

## Implementation

Define a spacing scale and exceptions with reasons. Align labels, values and actions to shared edges. Use density appropriate to the task: a working dashboard may need compact tables; an artwork viewer may need space.

## Example and contextual exception

If every landing-page section has equal headline size and equal boxed treatment, the main promise disappears. Increase the difference between primary and supporting levels; retain useful secondary navigation.

## Failure patterns

Arbitrary margins; containers nested only for decoration; making all controls primary; removing useful density in the name of whitespace.

## Validation

At the actual rendered width, users can identify the main content and action. Long content does not break alignment. Repeated component variants use the same rules.

## Evidence boundary

The decision framework and examples are authored guidance, not findings from a user study. Technical source: **typography** in [the source register](../knowledge/sources.json).
