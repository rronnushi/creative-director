# Taste: minimal foundations, expressive experiences

Load when choosing between plausible creative alternatives, not for every engineering edit. This philosophy starts with coherent structure, then invests expression where it makes the experience valuable or memorable. It is a default hypothesis, not a universal aesthetic.

Priority: explicit user constraints → established project direction → relevant private profile → public defaults. Technical correctness and evidence-based accessibility checks remain necessary even when a profile prefers something else. If a deliberate creative constraint conflicts with usability, explain the consequence and propose a workable alternative instead of quietly overruling the user.

## Preferences with reasons and exceptions

| Default | Reason | Contextual exception |
| --- | --- | --- |
| Clear hierarchy and strong composition | Makes the main task legible | Deliberate disorientation can serve an artwork; keep essential exits discoverable |
| Coherent identity over fashionable decoration | Builds recognition across states | A collage or maximalist identity can use many surfaces within an authored system |
| Meaningful interactions and purposeful motion | Feedback and continuity justify attention | Ambient motion may be the artwork itself; provide appropriate controls |
| Technical restraint | Reduces maintenance and failure points | A proven GPU requirement or complex existing framework may justify substantial infrastructure |
| Distinctive generative structure | Changes composition rather than merely parameters | A scientific comparison may intentionally hold structure constant |

## Anti-patterns and better decisions

Generic aesthetics are decisions without connection to the brief, not a blacklist of gradients or cards. Ask “what purpose does this serve here?” before rejecting a technique. Avoid arbitrary decoration, redundant features, unmotivated dependencies, repetitive procedural output and inconsistent systems.

Poor: every dashboard metric gets a new colour, border radius and animation. Better: consistent semantic colour roles and shared number alignment make comparison easier; reserve one expressive element for a meaningful signal. Exception: categorical datasets may need many colours with redundant labels.

Poor: “simplify” a working expert table into six oversized cards. Better: preserve useful density and improve grouping, alignment and filter feedback. Exception: a novice task with few facts may benefit from guided progressive disclosure.

Before recommending an aesthetic change, state the task benefit, identity fit, cost and exception. Use [comparisons](../knowledge/comparisons.json) for synthetic worked choices.
