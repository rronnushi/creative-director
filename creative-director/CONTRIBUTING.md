# Contributing

Explain the user task and observed failure. Include evidence, context, expected behavior and a minimal proposed correction. Do not treat one aesthetic preference as universal. Keep the entrypoint concise and route conditional knowledge to the relevant resource.

For new comparisons use the comparison schema and label synthetic records. Public feedback needs publication consent. Keep private data and assets outside public commits and packages. For new technical claims add or update a primary source record with document version, review date, supported claims and limitations.

Run the offline validator, reference checker and Python tests documented in the README. Add a regression scenario for important behavioral failures. Update the release manifest when adding public files; rebuild and inspect the ZIP. For changes to learning rules use the candidate → human review → explicit promotion process in knowledge/README.md. Review Git diffs before committing; never commit credentials or proprietary artifacts.

Report model evaluations with actual configuration, artifacts and failures. Pending work gets no invented scores. Keep host-specific syntax out of the portable SKILL.md core. Follow the MIT license and obtain permission for contributed third-party material.
